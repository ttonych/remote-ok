# G60S OK — инструкции для работы

## Объём

- Следовать `roadmap.md`: две поставки для Windows x64 — самостоятельная GUI-программа и дополнение Kodi 21/22.
- В первом релизе обрабатывать только кнопку OK. Не добавлять переназначение остальных кнопок, удержание или двойное нажатие без нового запроса пользователя.
- GUI должна поддерживать общий режим и режим MPC-BE/MPC-HC. Интерфейс и инструкции — на русском и английском.
- Общая логика HID должна переиспользоваться. Одно нажатие не должно обрабатываться двумя экземплярами; внутри Kodi приоритет его дополнению.

## Рабочий процесс

- Максимум разработки, сборки, проверки и отладки выполнять локально. Переходить к GitHub ближе к готовому результату, не использовать CI как основной цикл отладки.
- Сохранять рабочие прототипы в `outputs/G60S-OK` и `outputs/Kodi-G60S-OK` до подготовки замены. Временные данные и тестовые установки держать в `work/`.
- Проверять изменения подходящими тестами. Изменения GUI проверять по свежим снимкам реального окна в обеих локализациях.
- Не выдавать автоматические проверки за проверку физического пульта. Указывать реально проверенные версии программ и известные ограничения.
- Использовать отдельные тестовые профили Kodi; не менять пользовательские установки и настройки ради проверки.
- Обновлять отметки в `roadmap.md` только по факту завершения. Общаться с пользователем по-русски.

## Публикация

- Публичный репозиторий: `ttonych/remote-ok`. Название допускает поддержку других пультов; сейчас реализован только G60S Pro.
- Не публиковать личную почту пользователя. Для автора и коммитера использовать GitHub-адрес `noreply`; перед отправкой проверить метаданные коммитов и содержимое файлов.
- Перед созданием публичного репозитория определить владельца и имя. Не публиковать рабочую папку целиком: исключить настройки устройств, личные пути, диагностические журналы и временные загрузки.
- Один скрипт должен собирать проект локально и в GitHub Actions. Согласовывать версии двух пакетов с тегом релиза.
- **Все публичные релизные EXE и ZIP собирать только в GitHub Actions из исходников тега версии.** Не загружать локально собранные бинарники и не подменять ими результаты CI.
- Публиковать оба архива и SHA-256 только после успешной сборки и проверок. Указывать, что проверено автоматически, а что вручную.
